# 2.2 数据抽象

::: details INFO
来源：[2.2 Data Abstraction](https://www.composingprograms.com/pages/22-data-abstraction.html)
:::

环顾现实世界，我们想用程序表示的事物里，绝大多数都有复合结构。比如，一个地理位置由纬度和经度坐标组成。为了表示位置，我们希望编程语言能把经度和纬度**耦合**在一起，构成一个**对**（pair）——一种**复合数据**（compound data）值：程序可以把它当作一个概念单元来操作，但它也包含两个可以单独看待的部分。

使用复合数据，能提高程序的模块化程度。如果能把地理位置当作一个整体值来操作，程序中那些利用位置做计算的部分，就可以不必关心位置具体是怎么表示的。有一种通用技术，把程序中处理数据表示的部分与处理数据操作的部分隔离开来，这是一种强大的设计方法论，叫作**数据抽象**（data abstraction）。数据抽象让程序更容易设计、维护和修改。

数据抽象在性质上和函数抽象相似。建立函数抽象时，函数实现的细节可以隐藏起来，只要整体行为一致，这个函数本身换成任何别的函数都行。换句话说，我们建立的抽象把**函数的使用方式**和**函数的实现细节**分开。同理，数据抽象把复合数据值的使用方式与它的构造细节隔开。

数据抽象的基本思想，是让程序去操作抽象数据。也就是说，程序使用数据时，应尽量少对数据做假设。同时，具体的数据表示则作为程序的一个独立部分来定义。

程序的这两个部分——操作抽象数据的部分和定义具体表示的部分——由一小组函数连接起来，这组函数基于具体的表示来实现抽象数据。为了说明这一技术，我们来看看如何设计一组处理有理数的函数。

## 2.2.1 示例：有理数

有理数是整数之比，构成了实数的一个重要子类。像 `1/3` 或 `17/29` 这样的有理数通常写成：

```py
<分子>/<分母>
```

其中 `<分子>` 和 `<分母>` 都是**整数值的占位符**。要精确描述有理数的值，这两个部分缺一不可。实际上，直接把整数相除，得到的是 `float`（浮点）近似值，会丢掉整数的精确度。

```py
>>> 1/3
0.3333333333333333
>>> 1/3 == 0.333333333333333300000  # 整数除法得到是近似值
True
```

不过，只要把分子和分母组合起来，就能得到有理数的**精确表示**。

我们从函数抽象中知道，程序的某些部分还没实现，就可以先动手编程，而且照样有成效。让我们先**假设**已经有办法从分子和分母构造有理数，也有办法从一个有理数里取出它的分子和分母。再进一步假设，构造函数和选择函数就是下面这三个函数：

- `rational(n, d)` 返回分子为 `n`、分母为 `d` 的有理数
- `numer(x)` 返回有理数 `x` 的分子
- `denom(x)` 返回有理数 `x` 的分母

这里用到了一个强大的程序设计策略：**一厢情愿**（wishful thinking）。我们还没说有理数怎么表示，也没说 `numer`、`denom` 和 `rational` 该怎么实现。但即便如此，只要这三个函数真的定义好了，我们现在就能对有理数做加法、乘法、打印和相等性测试：

```py
>>> def add_rationals(x, y):
        nx, dx = numer(x), denom(x)
        ny, dy = numer(y), denom(y)
        return rational(nx * dy + ny * dx, dx * dy)

>>> def mul_rationals(x, y):
        return rational(numer(x) * numer(y), denom(x) * denom(y))

>>> def print_rational(x):
        print(numer(x), '/', denom(x))

>>> def rationals_are_equal(x, y):
        return numer(x) * denom(y) == numer(y) * denom(x)
```

现在，我们已经用选择函数 `numer`、`denom` 和构造函数 `rational` 定义了**有理数的操作**，但这些函数本身还没定义。我们需要某种办法，把分子和分母**粘合**成一个复合值。

## 2.2.2 对

为了能实现数据抽象的具体层，Python 提供了一种复合结构，叫作**列表**（list）。把表达式放进方括号、用逗号隔开，就能构造出列表。这样的表达式称为**列表字面量**。

```py
>>> [10, 20]
[10, 20]
```

访问列表元素有两种方式。第一种是我们熟悉的**多重赋值**，它把列表**解包**成一个个元素，分别绑定到不同的名称上。

```py
>>> pair = [10, 20]
>>> pair
[10, 20]
>>> x, y = pair
>>> x
10
>>> y
20
```

访问列表元素的第二种方式，是用**元素选择运算符**，同样写成方括号。方括号表达式紧跟在一个表达式之后，求值时不会得到 `list` 值，而是从前一个表达式的值里选出一个元素。这一点和列表字面量不同。

```py
>>> pair[0]
10
>>> pair[1]
20
```

Python 中的列表（以及大多数其他编程语言中的序列）都是 **0 索引**（0-indexed）的：索引 0 选中第一个元素，索引 1 选中第二个，依此类推。支持这种索引惯例的一个直觉是：**索引代表元素距离列表开头的偏移量**。

元素选择运算符对应的函数叫 `getitem`，它同样用 0 索引位置从列表里选元素。

```py
>>> from operator import getitem
>>> getitem(pair, 0)
10
>>> getitem(pair, 1)
20
```

双元素列表并不是 Python 中表示「对」的唯一方式。**任何把两个值捆绑成一个值的做法，都可以看作「对」**。列表只是常用的一种。列表也可以包含超过两个元素，这一点本章稍后会讲到。

**表示有理数。** 现在，我们可以把有理数表示成两个整数的「对」：一个分子、一个分母。

```py
>>> def rational(n, d):
        return [n, d]

>>> def numer(x):
        return x[0]

>>> def denom(x):
        return x[1]
```

结合前面定义的算术运算，我们就能用这些函数来操作有理数了。

```py
>>> half = rational(1, 2)
>>> print_rational(half)
1 / 2
>>> third = rational(1, 3)
>>> print_rational(mul_rationals(half, third))
1 / 6
>>> print_rational(add_rationals(third, third))
6 / 9
```

如上面的例子所示，我们的有理数实现没有把有理数化简成**最简分数**（lowest terms）。要弥补这个缺陷，可以修改 `rational` 的实现。如果我们有一个计算两个整数最大公约数的函数，就能在构造「对」之前，先把分子和分母化简。和许多好用的工具一样，这样的函数 Python 标准库里早就有了。

```py
>>> from fractions import gcd
>>> def rational(n, d):
        g = gcd(n, d)
        return (n//g, d//g)
```

地板除运算符 `//` 表示整数除法，它会把相除结果的小数部分向下取整。我们知道 `g` 能整除 `n` 和 `d`，所以这里的整数除法是**精确**的。修改后的 `rational` 实现，确保有理数总是以最简形式表示。

```py
>>> print_rational(add_rationals(third, third))
2 / 3
```

这一改进只改了构造函数，没有动任何实现实际算术运算的函数。

## 2.2.3 抽象屏障

在继续看更多复合数据和数据抽象的例子之前，先来想想有理数这个例子引出的几个问题。我们是依据构造函数 `rational`、选择函数 `numer` 和 `denom` 来定义各种运算的。总的来说，数据抽象的核心思想是：确定**一组基本操作**，对某类值的所有处理都用这组操作来表达，然后在处理数据时**只**用这些操作。这样限制操作的使用范围，修改抽象数据的底层表示就轻松多了，程序的行为也不用跟着改。

对有理数来说，程序的不同部分用不同的操作来处理有理数，如下表：

| 程序中……的部分                 | 把有理数看作 | 仅使用                                                                  |
| ------------------------------ | ------------ | ----------------------------------------------------------------------- |
| 用有理数做计算                 | 整体数据值   | `add_rational`、`mul_rational`、`rationals_are_equal`、`print_rational` |
| 创建有理数，或实现有理数运算   | 分子和分母   | `rational`、`numer`、`denom`                                            |
| 实现有理数的选择函数和构造函数 | 双元素列表   | 列表字面量和元素选择操作                                                |

上面每一层里，最后一列的函数都构成一道**抽象屏障**（abstraction barrier）。这些函数**由上一层调用，用下一层的抽象来实现**。

程序的某个部分本可以用较高层的函数，却改用了较低层的函数，就发生了**抽象屏障违反**（abstraction barrier violation）。例如，计算有理数平方的函数，最好基于 `mul_rational` 来实现，因为 `mul_rational` 不会对有理数的具体实现做任何假设。

```py
>>> def square_rational(x):
        return mul_rational(x, x)
```

如果直接引用分子和分母，就违反了一层抽象屏障：

```py
>>> def square_rational_violating_once(x):
        return rational(numer(x) * numer(x), denom(x) * denom(x))
```

如果假设有理数是用双元素列表表示的，就违反了两层抽象屏障：

```py
>>> def square_rational_violating_twice(x):
        return [x[0] * x[0], x[1] * x[1]]
```

抽象屏障让程序更容易维护和修改。**依赖某种特定数据表示**的函数越少，想改这种表示时，需要动的地方就越少。上面三种 `square_rational` 实现的行为都正确，但只有第一种对未来的变化具有**健壮性**（robustness）。就算改了有理数的表示方式，`square_rational` 也不用更新。相比之下，只要选择函数或构造函数的签名变了，`square_rational_violating_once` 就得改；只要有理数的底层实现变了，`square_rational_violating_twice` 就得更新。

## 2.2.4 数据的属性

抽象屏障塑造了我们思考数据的方式。有理数的有效表示**不限于任何特定的实现**（比如双元素列表）；**只要它由 `rational` 返回，能传给 `numer` 和 `denom`，就是有效的**。此外，构造函数和选择函数之间还必须保持**恰当的关系**。也就是说，如果我们用整数 `n` 和 `d` 构造出有理数 `x`，那么 `numer(x)/denom(x)` 必须等于 `n/d`。

一般来说，我们可以用一组选择函数和构造函数，外加一些**行为条件**（behavior conditions）来表达抽象数据。只要满足行为条件（比如上面的除法性质），这些选择函数和构造函数就构成了一类数据的有效表示。抽象屏障之下的实现细节可以变，但**只要行为不变，数据抽象就依然有效**，用这套数据抽象写的任何程序也仍然正确。

这种观点适用范围很广，包括我们用来实现有理数的「对」值。我们从没详细说过「对」到底是什么，只说语言提供了创建和操作双元素列表的手段。实现「对」所需要的全部行为，就是它能把两个值粘合在一起。把它写成行为条件，就是：

- 如果一个对 `p` 是由值 `x` 和 `y` 构造的，那么 `select(p, 0)` 返回 `x`，`select(p, 1)` 返回 `y`。

其实我们并不需要 `list` 类型来创建「对」。我们可以改为实现两个函数 `pair` 和 `select`，它们和双元素列表一样，完全满足上面的描述。

```py
>>> def pair(x, y):
        """返回一个表示「对」的函数"""
        def get(index):
            if index == 0:
                return x
            elif index == 1:
                return y
        return get

>>> def select(p, i):
        """返回对 p 中索引 i 处的元素"""
        return p(i)
```

有了这个实现，我们就能创建和操作对。

```py
>>> p = pair(20, 14)
>>> select(p, 0)
20
>>> select(p, 1)
14
```

这种高阶函数的用法，和我们关于「数据应该是什么样」的直觉完全对不上。但这些函数已经足以在程序中表示「对」。**函数足以表示复合数据**。

展示「对」的函数式表示，并不是说 Python 真的这样实现（出于效率考虑，列表的实现要直接得多），而是说它可以这样实现。这种函数式表示虽然晦涩，却是表示「对」的**完全合适的方式**，因为它满足了「对」必须满足的唯一条件。有了数据抽象这一做法，我们就能轻松地在不同表示之间切换。
