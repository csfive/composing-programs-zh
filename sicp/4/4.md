本节介绍一种声明式查询语言 logic，专为本书设计。它基于 [Prolog](http://en.wikipedia.org/wiki/Prolog) 和 [《计算机程序结构与解释》](http://mitpress.mit.edu/sicp/full-text/book/book-Z-H-29.html#%_sec_4.4.1) 中的声明式语言。数据记录表示为 Scheme 列表，查询表示为 Scheme 值。[logic](https://www.composingprograms.com/examples/logic/logic..html) 解释器是一个完整实现，依赖上一章的 Scheme 项目。

## 4.4.1 事实和查询

数据库存储记录，这些记录代表系统中的事实。查询解释器的用途，一是直接检索数据库记录中的事实集合，二是用逻辑推理从数据库中推导出新的事实。logic 中的事实语句由一个或多个列表组成，列表跟在关键字 fact 之后。简单事实就是单个列表。一位对美国历任总统感兴趣的养狗人，可能会用 logic 语言记录她这群狗的家谱，如下所示：

```
(fact (parent abraham barack))
(fact (parent abraham clinton))
(fact (parent delano herbert))
(fact (parent fillmore abraham))
(fact (parent fillmore delano))
(fact (parent fillmore grover))
(fact (parent eisenhower fillmore))
```

每一条事实都不像 Scheme 表达式那样是过程调用，而是一条被声明的关系。第一条事实声明的是：「狗亚伯拉罕是巴拉克的父亲。」关系类型不需要事先定义。关系不是被施加，而是与查询匹配。

查询也由一个或多个列表组成，但以关键字 query 开头。查询可以包含变量，也就是以问号开头的符号。查询解释器会把变量与事实匹配起来：

```
(query (parent abraham ?child))
Success!
child: barack
child: clinton
```

查询解释器会返回 `Success!`，表示该查询与数据库中的某条事实匹配，下面则列出变量 `?child` 的匹配替换结果。

**复合事实**：事实也可能包含变量和多个子表达式。多表达式事实以结论开头，后面跟着假设。结论要成立，所有假设都必须得到满足：

```
(fact <conclusion> <hypothesis0> <hypothesis1> ... <hypothesisN>)
```

例如，可以基于数据库中已有的父母事实，声明关于孩子的事实：

```
(fact (child ?c ?p) (parent ?p ?c))
```

上面的事实可以读作：「`?c` 是 `?p` 的孩子，只要 `?p` 是 `?c` 的父母。」现在，查询就可以引用这条事实：

```
(query (child ?child fillmore))
Success!
child: abraham
child: delano
child: grover
```

上面的查询需要查询解释器把定义 child 的事实，与关于 fillmore 的多条父母事实结合起来。使用这门语言的人不必知道这些信息是怎么组合的，只需知道结果具有特定的形式。至于根据已有事实证明 `(child abraham fillmore)` 为真，那是查询解释器的事。

查询不必包含变量，也可以只是验证一条事实：

```
(query (child herbert delano))
Success!
```

没有匹配到任何事实的查询会返回失败：

```
(query (child eisenhower ?parent))
Failed.
```

**否定**。使用特殊关键字 not，可以检查某个查询是否不与任何事实匹配：

```
(query (not <relation>))
```

`<relation>` 失败时，这个查询成功；`<relation>` 成功时，这个查询失败。这个思路称为否定即失败（negation as failure）。

```
(query (not (parent abraham clinton)))
Failed.
(query (not (parent abraham barack)))
Failed.
```

有时，否定即失败的结果，可能和人对否定的直觉不一致。想想下面这个查询会得到什么结果：

```
(query (not (parent abraham ?who)))
```

为什么这个查询会失败？按理说，有很多符号都能绑定到 `?who`，让这个查询成立。但按照否定的步骤，我们要先检查关系 `(parent abraham ?who)`。这个关系会成功，因为 `?who` 既可以绑定到 `barack`，也可以绑定到 `clinton`。既然这个关系成功，它的否定就必然失败。

## 4.4.2 递归事实

logic 语言也允许递归事实。也就是说，一条事实的结论可能取决于一条含有相同符号的假设。例如，祖先关系用两条事实定义。如果 `?a` 是 `?y` 的父母，或者 `?a` 是 `?y` 某个祖先的父母，那么 `?a` 就是 `?y` 的祖先：

```
(fact (ancestor ?a ?y) (parent ?a ?y))
(fact (ancestor ?a ?y) (parent ?a ?z) (ancestor ?z ?y))
```

这样，一个查询就能列出 herbert 的所有祖先：

```
(query (ancestor ?a herbert))
Success!
a: delano
a: fillmore
a: eisenhower
```

**复合查询**。查询可以包含多个子表达式，此时必须能给变量赋一组符号，让所有子表达式同时得到满足。如果一个变量在查询中出现多次，它在每处上下文中都必须取相同的值。下面的查询找出 herbert 和 barack 共同的祖先：

```
(query (ancestor ?a barack) (ancestor ?a herbert))
Success!
a: fillmore
a: eisenhower
```

递归事实可能需要很长的推理链，才能把查询与数据库中已有的事实匹配起来。例如，要证明事实 `(ancestor fillmore herbert)`，我们必须依次证明下面每一条事实：

```
(parent delano herbert)       ; (1), a simple fact
(ancestor delano herbert)     ; (2), from (1) and the 1st ancestor fact
(parent fillmore delano)      ; (3), a simple fact
(ancestor fillmore herbert)   ; (4), from (2), (3), & the 2nd ancestor fact
```

这样，一条事实就能蕴含大量附加事实，甚至无穷多条，只要查询解释器能够发现它们。

**层级事实**。到目前为止，每个事实和查询表达式都是一个符号列表。此外，事实和查询列表还可以包含列表，这提供了一种表示层级数据的方法。每只狗的颜色可以连同名字，一起存成一条附加记录：

```
(fact (dog (name abraham) (color white)))
(fact (dog (name barack) (color tan)))
(fact (dog (name clinton) (color white)))
(fact (dog (name delano) (color white)))
(fact (dog (name eisenhower) (color tan)))
(fact (dog (name fillmore) (color brown)))
(fact (dog (name grover) (color tan)))
(fact (dog (name herbert) (color brown)))
```

查询可以写出层级事实的完整结构，也可以让变量匹配整个列表：

```
(query (dog (name clinton) (color ?color)))
Success!
color: white
(query (dog (name clinton) ?info))
Success!
info: (color white)
```

数据库的强大之处，很大程度上在于查询解释器能在单个查询里结合多种事实。下面的查询找出所有这样的狗对：一只是另一只的祖先，且两只颜色相同：

```
(query (dog (name ?name) (color ?color))
       (ancestor ?ancestor ?name)
       (dog (name ?ancestor) (color ?color)))
Success!
name: barack color: tan ancestor: eisenhower
name: clinton color: white ancestor: abraham
name: grover color: tan ancestor: eisenhower
name: herbert color: brown ancestor: fillmore
```

变量既能引用层级记录中的列表，也能用点记法引用。跟在点后面的变量，匹配事实列表中剩下的部分。点分列表可以出现在事实或查询中。下面的例子列出一连串祖先，为狗构建家谱。年轻的 barack 承袭了一条古老的总统名犬血脉：

```
(fact (pedigree ?name) (dog (name ?name) . ?details))
(fact (pedigree ?child ?parent . ?rest)
      (parent ?parent ?child)
      (pedigree ?parent . ?rest))
(query (pedigree barack . ?lineage))
Success!
lineage: ()
lineage: (abraham)
lineage: (abraham fillmore)
lineage: (abraham fillmore eisenhower)
```

声明式编程或逻辑编程，能非常高效地表达事实之间的关系。例如，我们要表达「两个列表可以拼接成一个更长的列表，其中先放第一个列表的元素，再放第二个列表的元素」，就要写出两条规则。第一条是基本情况，声明把空列表接在任意列表后面，得到的还是那个列表；

```
(fact (append-to-form () ?x ?x))
```

第二条是递归事实，声明：首元素为 `?a`、其余部分为 `?r` 的列表，与列表 `?y` 拼接后，形成首元素为 `?a`、其余部分为拼接所得的 `?z` 的列表。这个关系要成立，就必须有 `?r` 与 `?y` 拼接成 `?z`：

```
(fact (append-to-form (?a . ?r) ?y (?a . ?z)) (append-to-form ?r ?y ?z))
```

有了这两条事实，查询解释器就能算出任意两个列表拼接的结果：

```
(query (append-to-form (a b c) (d e) ?result))
Success!
result: (a b c d e)
```

此外，它还能算出所有可能的列表对 `?left` 和 `?right`，这些列表对拼接起来能得到列表 `(a b c d e)`：

```
(query (append-to-form ?left ?right (a b c d e)))
Success!
left: () right: (a b c d e)
left: (a) right: (b c d e)
left: (a b) right: (c d e)
left: (a b c) right: (d e)
left: (a b c d) right: (e)
left: (a b c d e) right: ()
```

虽然查询解释器看起来相当智能，但我们会看到，它只是把同一个简单操作重复多次，才找出这些组合：在环境里匹配两个含有变量的列表。
